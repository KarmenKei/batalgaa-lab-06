# Лаборатори №6 — Тест тохиолдол боловсруулах
**Хичээл:** F.CSA313 — Программ хангамжийн чанарын баталгаа ба тест  
**Оюутан** Ц.Бэлгүтэй / B232270053
**Сэдэв:** Category-Partition болон PICT аргаар тест тохиолдол боловсруулах  
**Огноо:** 2026-10-13

## 1. Зорилго

Энэхүү лабораторийн ажлаар тест сонголтын хоёр аргыг хэрэгжүүлэв.

1. **Category-Partition:** Банкны шилжүүлгийн функцийн оролт, нөхцөлүүдийг ангилж, төлөөлөх утгууд болон хязгаарлалтуудыг тодорхойлох.
2. **PICT (Pairwise Independent Combinatorial Testing):** Оролтын параметрүүдийн хосолсон утгуудыг хамруулах тестийн багц үүсгэж, 2-way болон 3-way хамрах хүрээг харьцуулах.

## 2. Банкны шилжүүлгийн функцийн тодорхойлолт

Тестлэх функц нь дараах хүсэлтээр мөнгө шилжүүлнэ гэж үзэв.

```http
POST /transfer
Content-Type: application/json
```

```json
{
  "from": "ACC001",
  "to": "ACC002",
  "amount": 10000,
  "currency": "MNT"
}
```

Амжилттай шилжүүлгийн хариу нь `HTTP 201 Created` байна. Алдааны хариу нь HTTP статус болон тодорхой алдааны кодтой байна. Доорх код, статусууд нь тест боловсруулахад ашигласан **санал болгож буй API-ийн гэрээ (test specification)** бөгөөд бодит сервер дээр баталгаажуулсан үр дүн биш.

## 3. Part A — Category-Partition арга

### 3.1 Оролтын ангиллууд

| Ангилал | Төлөөлөх утгууд |
|---|---|
| From account | Existing, Missing, Frozen, LowBalance, AtLimit |
| To account | Existing, Missing, Frozen, SameAsFrom |
| Amount | Normal, Zero, Negative, AboveBalance, AboveLimit |
| Currency | MNT, USD, EUR |

Эдгээр ангилал нь дансны төлөв, шилжүүлгийн дүн болон валютын ялгаатай нөхцөлүүдийг хамруулна.

### 3.2 Ангиллын хязгаарлалт ба дүрмүүд

- **[ERROR]** Шилжүүлэгч данс байхгүй эсвэл царцаалттай бол шилжүүлгийг хийхгүй.
- **[ERROR]** Хүлээн авагч данс байхгүй эсвэл царцаалттай бол шилжүүлгийг хийхгүй.
- **[ERROR]** Шилжүүлэгч болон хүлээн авагч данс ижил байж болохгүй.
- **[ERROR]** Шилжүүлгийн дүн тэг, сөрөг эсвэл дансны боломжит үлдэгдлээс их байж болохгүй.
- **[ERROR]** Шилжүүлгийн дүн өдрийн үлдсэн лимитээс их байж болохгүй.
- **[SINGLE]** Нэг тестэд үндсэндээ нэг алдааны нөхцөлийг тусгаарлан шалгаж, алдааны шалтгааныг тодорхой болгоно.
- **[IF]** Валют нь MNT биш бол үлдэгдэл болон лимиттэй харьцуулахдаа тохирох валютын ханшийг ашиглана.

### 3.3 Олон алдаа зэрэг үүсэх үеийн эрэмбэ

Нэг хүсэлтэд олон алдааны нөхцөл давхцвал тестийн үр дүн тогтвортой байхын тулд дараах шалгах эрэмбийг **энэ лабораторийн санал болгож буй спецификац** болгон авлаа.

1. `ERROR_FROM_NOT_FOUND`
2. `ERROR_FROM_FROZEN`
3. `ERROR_TO_NOT_FOUND`
4. `ERROR_TO_FROZEN`
5. `ERROR_SAME_ACCOUNT`
6. `ERROR_BAD_AMOUNT`
7. `ERROR_INSUFFICIENT_FUNDS`
8. `ERROR_DAILY_LIMIT`

Энэ дараалал нь бодит системийн баталгаажсан зан төлөв биш. Хэрэв бодит API-ийн гэрээ өөр эрэмбэ заасан бол тестийн хүлээгдэж буй үр дүнг түүнд нийцүүлэн өөрчилнө.

### 3.4 Тест тохиолдлын жишээнүүд

Доорх жишээнүүдэд бусад шаардлагатай нөхцөл хүчинтэй, зөвхөн дурдсан алдааны нөхцөл үүссэн гэж үзэв.

| ID | Нөхцөл | Хүлээгдэж буй үр дүн |
|---|---|---|
| CP-01 | Хүчинтэй данс, эерэг дүн, MNT | `201 Created` |
| CP-02 | Хүчинтэй данс, USD | `201 Created` |
| CP-03 | Хүчинтэй данс, EUR | `201 Created` |
| CP-04 | Шилжүүлэгч данс байхгүй | `404`, `ERROR_FROM_NOT_FOUND` |
| CP-05 | Шилжүүлэгч данс царцаалттай | `409`, `ERROR_FROM_FROZEN` |
| CP-06 | Хүлээн авагч данс байхгүй | `404`, `ERROR_TO_NOT_FOUND` |
| CP-07 | Хүлээн авагч данс царцаалттай | `409`, `ERROR_TO_FROZEN` |
| CP-08 | Хоёр дансны ID ижил | `400`, `ERROR_SAME_ACCOUNT` |
| CP-09 | Дүн тэгтэй тэнцүү | `400`, `ERROR_BAD_AMOUNT` |
| CP-10 | Дүн сөрөг | `400`, `ERROR_BAD_AMOUNT` |
| CP-11 | Үлдэгдлээс их дүн | `422`, `ERROR_INSUFFICIENT_FUNDS` |
| CP-12 | Өдрийн лимитээс их дүн | `422`, `ERROR_DAILY_LIMIT` |

Эдгээр статус болон алдааны код нь санал болгож буй тестийн oracle юм. Бодит системийн гэрээтэй нийцэж байгаа эсэхийг тусад нь шалгана.

## 4. Part B — PICT ашиглан тест үүсгэх

### 4.1 PICT хэрэгсэл

PICT нь параметр бүрийн бүх боломжит утгын хослолыг бүрэн жагсаахын оронд тодорхой түвшний хосолсон хамрах хүрээг хангах тестийн багц үүсгэдэг.

Энэ лабораторид PICT-ийн эх кодыг локал орчинд бүтээж, командын мөрөөс ажиллуулсан. Build болон ашиглах зааврын нотолгоо `results/pict-build.txt` файлд хадгалагдсан.

### 4.2 Хөтөчийн нийцтэй байдлын загвар

`browser.model` файлд дараах параметрүүдийг тодорхойлсон.

- Browser: Chrome, Firefox, Safari, Edge
- OS: macOS, Windows, Linux
- Network: Fast, Slow, Offline
- Login: Valid, Invalid

| Хамрах хүрээ | Команд | Үүссэн тестийн мөр |
|---|---|---:|
| 2-way | `pict browser.model` | 12 |
| 3-way | `pict browser.model /o:3` | 36 |

Үүсгэсэн тестүүдийг `results/browser-2way.txt` болон `results/browser-3way.txt` файлуудад хадгалсан.

2-way нь параметрүүдийн бүх боломжит хос утгыг хамруулахыг зорьдог бол 3-way нь гурван параметрийн утгын гурвалуудыг хамруулна. Иймээс 3-way нь илүү өргөн хослолын хамрах хүрээтэй боловч ихэвчлэн илүү олон тест шаарддаг.

### 4.3 Банкны шилжүүлгийн загварууд

| Файл | Зориулалт | Үүссэн тестийн мөр |
|---|---|---:|
| `transfer-nc.model` | Хязгаарлалтгүй үндсэн загвар | 26 |
| `transfer.model` | Хязгаарлалттай загвар | 26 |
| `transfer-neg.model` | Сөрөг тестийн утгууд тэмдэглэсэн загвар | 36 |

Үүсгэсэн үр дүнг дараах файлуудад хадгалсан.

- `results/transfer-nc.txt`
- `results/transfer.txt`
- `results/transfer-neg.txt`

Энд тестийн мөрийн тоонд баганын нэр бүхий эхний мөр ороогүй. Текст файл дахь мөрийн нийт тоо үүнээс нэгээр их байна.

### 4.4 Хязгаарлалттай ба хязгаарлалтгүй загварын харьцуулалт

`transfer-nc.model` нь бүх ангиллын утгуудыг хязгаарлалтгүйгээр тодорхойлно. `transfer.model` файлд дараах дүрмүүдийг нэмсэн.

```text
IF [From] = "Missing" THEN [Amount] = "Normal";
IF [To] = "Missing" THEN [Amount] = "Normal";
```

Эдгээр дүрэм нь данс байхгүй үед бусад алдааны утгуудтай хослох боломжийг хязгаарлах зорилготой.

PICT-ийн статистик гаралт:

| Загвар | Combinations | Generated tests |
|---|---:|---:|
| `transfer-nc.model` | 107 | 26 |
| `transfer.model` | 99 | 26 |
| `transfer-neg.model` | 22 | 36 |

`Combinations` нь PICT-ийн тооцсон хамрах хослолын тоог илэрхийлнэ; энэ нь параметрүүдийн бүх боломжит бүрэн хослолын тоо гэсэн үг биш. `Generated tests` нь үүсгэсэн тестийн тоо юм.

Хязгаарлалт нэмэхэд тооцогдсон хослолын тоо 107-оос 99 болж буурсан боловч үүсгэсэн тестийн тоо 26 хэвээр байна. Сөрөг утгуудыг тэмдэглэсэн загвар нь өөр утгуудын хүрээтэй тул 36 тест үүсгэсэн.

PICT-ийн сөрөг утгын `~` тэмдэглэгээ нь тухайн утгыг сөрөг тестийн утга болгон тэмдэглэдэг. Үүссэн мөрүүдийг шалгаж, хязгаарлалттай хослолууд хүссэнээрээ ажиллаж байгаа эсэхийг баталгаажуулах шаардлагатай.

### 4.5 Үүсгэсэн тестээс тест тохиолдол гаргах

PICT-ээс гарсан мөрүүдийг шууд бодит API-ийн үр дүн гэж үзэхгүй. Тэдгээрийг тестийн оролтын хувилбар болгон хувиргаж, урьдчилсан нөхцөл болон хүлээгдэж буй үр дүнг тодорхойлно.

**PICT-TC-01 — Амжилттай шилжүүлэг**

- **Setup:** ACC001 болон ACC002 дансууд идэвхтэй; ACC001-д хангалттай үлдэгдэлтэй; өдрийн лимит хүрээгүй.
- **Input:** `from=ACC001`, `to=ACC002`, `amount=10000`, `currency=MNT`.
- **Oracle:** `201 Created`; шилжүүлэгчийн үлдэгдэл 10000-аар буурч, хүлээн авагчийн үлдэгдэл 10000-аар нэмэгдэнэ.

**PICT-TC-02 — Шилжүүлэгч данс байхгүй**

- **Setup:** Шилжүүлэгч дансны ID бүртгэлгүй; бусад нөхцөл хүчинтэй.
- **Input:** `from=Missing`, `to=ACC002`, `amount=Normal`, `currency=MNT`.
- **Oracle:** `404 Not Found`, `ERROR_FROM_NOT_FOUND`; үлдэгдэл өөрчлөгдөхгүй.

**PICT-TC-03 — Хүчингүй дүн**

- **Setup:** Хоёр данс хүчинтэй бөгөөд идэвхтэй.
- **Input:** Хүчинтэй шилжүүлэгч, хүлээн авагчтай боловч `amount=0`.
- **Oracle:** `400 Bad Request`, `ERROR_BAD_AMOUNT`; шилжүүлэг хийгдэхгүй.

Эдгээр нь загварын утгыг тест тохиолдол болгон хувиргах жишээ юм. PICT-ийн гаралтаас яг аль мөрийг сонгосныг тайланд баталгаажуулахдаа тухайн мөрийг `results/transfer*.txt` файлаас тулгана.

## 5. Аргуудын харьцуулалт

| Үзүүлэлт | Category-Partition | PICT / Pairwise |
|---|---|---|
| Гол зорилго | Ангилал, нөхцөл, хязгаарлалтыг системтэй тодорхойлох | Параметрүүдийн хосолсон утгуудыг хамруулах |
| Давуу тал | Хүлээгдэж буй үр дүн болон алдааны нөхцөлийг тайлбарлахад тохиромжтой | Олон параметрийн хослолын тоог багасгахад тусалдаг |
| Хязгаарлалт | Тестийг гараар сонгоход алдаа эсвэл орхигдол үүсэж болно | Бизнесийн дүрэм, хүлээгдэж буй хариуг өөрөө тодорхойлохгүй |
| Хэрэглээ | Шаардлага, алдааны зан төлөвийг тодорхойлох | Хослолын хамрах хүрээг нэмэгдүүлэх |

Эдгээр аргыг хамтад нь ашигласнаар Category-Partition нь тестлэх шаардлагуудыг тодорхойлж, PICT нь сонгосон параметрүүдийн хосолсон хувилбаруудыг үр ашигтай үүсгэхэд тусална.

## 7. Дүгнэлт

Энэ лабораторийн ажлаар Category-Partition аргаар банкны шилжүүлгийн тестлэх ангилал, төлөөлөх утга, алдааны нөхцөлүүдийг тодорхойлж, PICT ашиглан 2-way болон 3-way тестийн багцуудыг үүсгэв. Мөн хязгаарлалтгүй, хязгаарлалттай болон сөрөг утгатай загваруудын гаралтыг харьцууллаа.

Тестийн тоо бага байх нь дангаараа чанарын баталгаа биш. Загварын хязгаарлалт зөв эсэх, үүсгэсэн мөрүүд шаардлагыг хамарч байгаа эсэх, хүлээгдэж буй үр дүн бодит API-ийн гэрээтэй нийцэж байгаа эсэхийг тусад нь шалгах хэрэгтэй.
